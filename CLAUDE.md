## [LEGACY_DEBT_AND_RISKS]

### Critical / user-visible
1. **~~`--webui` is consumed as the SystemGroup GUID~~** **FIXED in #29** (`new_applepie.py:1227-1245`). `Hacktivating` now treats `sys.argv[1]` as a GUID **only** when it does not start with `-` (CLI custom-GUID feature preserved); `--webui`, other flags, and no-argv all fall back to `get_guid_auto()`, restoring the original GUI default. Regression test: web-UI launch no longer substitutes `"--webui"` into stage3 (`GOODKEY`).
2. **Zombie busy state on failure.** `busy=True` set at `:1286` (and via `_Button.hide` `:148`); reset ONLY on success (`:1598`). Every `sys.exit()` failure path (`:1318, 1357, 1361, 1375, 1395, 1421, 1452, 1556`) leaves `busy=True`, frozen progress, and **no failure popup** — the browser shows a permanently stuck progress bar; the only clue is the last console log line. (High — needs `finally`-based reset + failure popup.)
3. **Staging `rmtree` vs live phone downloads — race** (`:1210-1211`). `generate_payloads` wipes the live web root; a concurrent/retry run mid-download truncates files or 404s the phone; `ignore_errors=True` silently swallows Windows delete failures → stale files. (High for the exploit path — version the staging root per generation or stop the server before wipe.)
4. **Port-8001 three-way mismatch.** `PAYLOAD_PORT=8001` (`:191`), server falls back to 8001–8010 (`:819`), URLs embed actual `_payload_port` (`:1213`) — but the firewall rule hardcodes `localport=8001` (`:955`) and the intro check is named "port 8001" (`:1025`). If 8001 is busy, server binds 8002+ → phone blocked, while requirements checks still pass. (High — derive rule/check from `_payload_port`.)

### Medium
5. **`pymobiledevice3.exe` shim breaks the "AIO standalone" claim.** Reboot + all AFC ops shell to a 106 KB pip launcher that needs the host's site-packages; the same API is also imported Python-side (`:33-34`). On a clean machine the exe path fails. (Medium-High.)
6. **No busy/idempotency guard on `/api/unlock`** — double POST = two concurrent Hacktivating threads racing on staging, reboots, `self.guid`. (Medium.)
7. **`reboot_device` lies on double fallback** — `input()` then `return True` (`:476-477`); reconnection wait checks only exit code 0, which ideviceinfo returns even on "No device found". (Medium.)
8. **`check_requirements` blocks ~5 s** with no device (`:854`). (Medium — cache the last ideviceinfo result.)
9. **Non-daemon `Hacktivating` blocks shutdown** mid-run (10+ min join). (Medium.)
10. **Unlocked state never resets `connected`/stale fields** after scan-thread `break` (`:1641-1643`). (Medium-Low.)

### Dependencies / supply chain
11. **CVE-2026-25645 in requests 2.32.5** (`extract_zipped_paths` insecure temp; fixed 2.33.0/2.34.2) — Low practical risk here (app only does GETs), upgrade recommended. Flask 3.1.3 OK (CVE-2026-27205 fixed in it). pymobiledevice3 10.8.1 latest, no CVEs. PyInstaller 6.22.1 (6.22.2 out) OK.
12. **libcurl 8.19.0 in `bin/` is outdated** (26 CVEs fixed in 8.20.0); Low exploitability (only reachable via usbmuxd path) but poor supply-chain hygiene. OpenSSL 3.6.2 is patched. No sha256 lockfile/manifest for any binary. (Medium-Low.)
13. **Dead dep PyQt5 5.15.11** still installed (EOL 2025-05-26, unpatched CVEs) — uninstall; **pillow** is test-only (now excluded from `requirements.txt`).
14. **Git hygiene:** no `.gitignore`; `__pycache__/*.pyc` committed; binaries committed without hashes; single `init` commit. (Low-Medium.)

### Cross-module coupling (top break points)
15. **`web_state` implicit contract** — 19 stringly-typed keys, no schema/validation; keys `supported` and `scan_paused` are written/served but never rendered by app.js; the only schema is `test_webui.py:71-78`. Renaming a key breaks silently across engine→Flask→browser. (Medium.)
16. **Double module import:** `webui.py:185` lazy `from new_applepie import ApplePieEngine` re-executes the module as a second instance (double banner, second `web_state`/`_web_lock`) — harmless only because `apply_firewall_rule` is static. (Low-Medium.)
17. **Log truncation vs app.js delta counter:** `_LogProxy` caps at 500 (`:118-119`) but `app.js` uses a monotonic `lastLogs` index (`:40-49`) → console freezes/skips after truncation. (Low.)
18. **Hidden coupling in data templates:** `http://194.99.21.156:8001/badfile.plist` also lives inside `data/downloads.28.png` and is patched by literal string replace (`:1249`) — template change silently breaks the patch. (Low-Medium.)
19. **Path-resolution divergence:** `_resource`/`_data` use `sys._MEIPASS`; `run_short_command` uses `Path(__file__).parent` — coincidentally equal when frozen, but two idioms for the same assets. (Low.)

### Doc contradictions found
- README `:53` calls 3uTools "optional", but `check_intro_requirements` includes it in `all_passed` (`:1027`) and app.js **locks Close** on failure → de-facto mandatory.
- README unit-test count "31" matches `test_webui.py` (31 methods); live 28; pages 7.

### Target architecture (descriptive, NOT implemented — for the refactor phase)
Carve the god object into: `device_driver` (subprocess wrappers + DeviceInfo dataclass, one reboot), `guid_service` (live logarchive pipeline only), `payload_builder` (pure `(prd, guid, sn, ver) -> StageBundle`, token-map replaces inline `.replace` chains), `staging_server` (port + base_url + lifecycle, never rmtree a live root), `afc_transport` (pymobiledevice3 only, drop ifuse), `state_bridge` (typed `StateStore` + `StateSnapshot` dataclass replacing `web_state` — the direct `_web()`/`_log()` writes are the seam it formalizes), `requirements_service`, `web_transport` (Flask unchanged shape), `workflow` (Hacktivating as a state machine: WAITING_GUID → GENERATING → DEPLOYING → REBOOTING → COPYING → DONE, `busy` reset in `finally`, no `sys.exit()` in threads). Recommended order: **delete dead code first (~340 lines, zero-risk, AST-verified)** → staging_server → device_driver (unify subprocess/reboot) → payload_builder → guid_service → state_bridge (highest-touch) → requirements_service + afc_transport → workflow (highest-risk, needs a device-in-loop).
